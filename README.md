# Alder

Альбом натуралиста: фото или поиск растения, личное имя для него, коллекция по сезонам, группам и странам, слой «значений» (фольклор, астроботаника, этимология). PWA, работает офлайн, без сборки.

## Запуск

```bash
cd alder
python3 -m http.server 8137      # или: npx serve .
# открыть http://localhost:8137
```

Service worker и камера требуют `localhost` или HTTPS. Для телефона: выложить на любой статический хостинг с HTTPS (Cloudflare Pages, Netlify, GitHub Pages) и «Добавить на главный экран».

## Иллюстрации

У каждого растения есть рисунок (`js/art.js`, ключ — `id` растения из каталога). Он показывается в каталоге, в карточке и в альбоме, пока нет фото, и остаётся как «этикетка» вида, когда фото добавлено (фото лежит рядом, в углу карточки и на странице записи). Это первый, схематичный проход. Заменить любой рисунок можно по одному: вернуть SVG-строку для нужного `id`. У видов, которых нет в каталоге, рисуется общий «побег».

## Рядом (поиск растений по месту)

Вкладка «Рядом»: пользователь определяет место (геопозиция или город), приложение запрашивает у GBIF число наблюдений каждого растения каталога в радиусе 10–100 км. Не найденные растения показываются закрытыми силуэтами с числом наблюдений рядом, найденные — цветными. В карточке растения секция «Где искать рядом» показывает места, где его чаще всего наблюдали (кластеры точек ~2 км, названия из OSM) и месяцы пика. При сохранении находки можно запомнить её место.

Важно:
- Это данные реальных наблюдений (в основном iNaturalist через GBIF), а не догадки ИИ. ИИ можно подключить позже для пояснений и чата, но факты о местах должны остаться за данными.
- Плотность данных сильно разная: Москва и Петербург хорошо, региональные города слабее, юг и малонаселённые места бедно. Для таких мест приложение честно пишет «мало данных».
- Названия кластеров сейчас чаще районы, чем парки (обратное геокодирование Nominatim). Следующий шаг: запрос парков и природных территорий из OSM (Overpass) и привязка точек к ним. Overpass из моей среды недоступен, проверить нужно в браузере.
- Публичный Nominatim ограничен ~1 запросом в секунду и не для большого трафика: для публикации нужен свой геокодер или платный сервис. Запросы к GBIF стоит проксировать и кэшировать на своём сервере.
- Каталог следует за местом: город из списка или геопозиция ближе 400 км к известному городу переключает страну (Россия или ОАЭ). Вне этих зон остаётся прежний каталог и «Рядом» честно пишет, что наблюдений нет.
- Растения разные в разных местах, поэтому «Рядом» показывает только то, что реально замечали в радиусе: в Петербурге это морошка, черника, багульник и борщевик Сосновского, в Сочи кизил и самшит, в Дубае гаф и мангры. Остальные карточки собраны в «не замечены рядом».
- ОАЭ: открытых наблюдений меньше, чем в Москве или Петербурге (по виду от единиц до сотен в радиусе 50 км), городские декоративные растения (бугенвиллея, олеандр) в базах почти не представлены. Раздел «Мало данных» будет появляться часто.
- Список городов (Петербург и Ленобласть, большие города, 7 эмиратов) задаётся в `CITIES` (`js/geo.js`), каждому городу соответствует группа и страна.
- Охрана: приложение просит наблюдать и фотографировать, не срывать. Для видов из Красных книг нужна отдельная пометка по регионам (пока нет).

## Определение по фото

Бесплатный ключ: https://my.plantnet.org. Вводится в разделе «Я», хранится только на устройстве.
Если сервис не отдаёт CORS-заголовки для браузера, запросы нужно пустить через свой тонкий прокси (см. `plantnet()` в `identify.js`). Проверить на реальном ключе.

## Принципы контента

- Слой «значений» всегда помечается «предание, не наука». У каждого пункта указан источник.
- Планеты — только по Калпеперу (1653); знаки выводятся по классическим домам планет.
- Кельтский календарь деревьев — конструкция Р. Грейвса 1948 года, а не древность. Так и написано в интерфейсе.
- Раздел «В быту» — только то, в чём мы уверены. Всё остальное не приводится. Токсичные растения помечены, предупреждение всегда видно и не сворачивается.
- `needsReview: true` — текст написан по памяти и ждёт сверки с источниками. **Перед публикацией проверить все карточки**, особенно предания с датами и именами.
